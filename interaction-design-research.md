# Interaction Design Research: Dense Per-Row Configuration Panels

**Scope:** a DSH plugin settings page where each provider group renders ~60–70 model rows, each repeating four control clusters — visibility checkbox, context-length chips (200K/256K/400K/1M), vision toggle, star toggle: ~400–500 controls per group.

---

## 1. Choosing controls for a small set

The governing distinction is **mutually exclusive vs. independent**, not visual style. NN/g: radio buttons are for options that are "mutually exclusive and the user must select exactly one choice"; checkboxes when "the user may select any number of choices, including zero, one, or several"; a stand-alone checkbox "for a single option that the user can turn on or off" ([NN/g](https://www.nngroup.com/articles/checkboxes-vs-radio-buttons/)). Here context length is mutually exclusive while visibility, vision, and star are independent booleans — yet all four render as near-identical chips.

Primer (GitHub) is explicit on counts: a segmented control "should have 2–5 choices with text labels, or up to 6 icon-only segments. Too many choices can be difficult to parse and take up too much horizontal space. If there are more than 5 choices, use another choice selection pattern such as a group of radio inputs or a dropdown menu" ([Primer](https://primer.style/product/components/segmented-control/)). Four presets is fine *within* a row; the failure is **multiplication across rows**.

Apple's HIG draws the same boundary: "if you need to support other types of actions — such as choosing from a list of items — use a different component, like a pop-up button" ([Apple HIG](https://developer.apple.com/design/human-interface-guidelines/toggles)). Android treats toggle saturation as a constraint: "Use switches over checkboxes when possible. Checkboxes can be used: ... **To avoid having too many switches on the screen**" ([Android](https://source.android.com/docs/core/settings/settings-guidelines)). Material confirms chip semantics: segments are toggle buttons with `aria-pressed` inside `role="group"` ([MDC](https://github.com/material-components/material-components-web/tree/master/packages/mdc-segmented-button)).

## 2. Progressive disclosure: expansion vs. inline

NN/g: "Initially, show users only a few of the most important options. Offer a larger set of specialized options upon request." The payoff is measured: "progressive disclosure helps novice users avoid mistakes... For advanced users, the smaller initial display also saves them time because they avoid having to scan past a large list of features they rarely use. Progressive disclosure thus improves 3 of usability's 5 components: **learnability, efficiency of use, and error rate**." Two constraints follow: disclose "everything that users frequently need up front," and "the primary list can't contain too many options or you'll fail to sufficiently focus users' attention" ([NN/g](https://www.nngroup.com/articles/progressive-disclosure/)).

Material supplies the row-level mechanism — expandable rows "present large amounts of data in a small space" ([Material](https://github.com/material-components/material-components-web/tree/master/packages/mdc-data-table)); Carbon likewise: "rows can be expanded to progressively disclose information" ([Carbon](https://carbondesignsystem.com/components/data-table/usage/)). Android gives a threshold: "Settings that are not frequently used should be hidden. Use 'Advanced' only when there are **at least 3 items to hide**," with a subtext naming what is hidden ([Android](https://source.android.com/docs/core/settings/settings-guidelines)).

**Counter-evidence matters.** "Each step involved in expanding the accordion—scrolling the page, scanning the headings, deciding which one to expand, targeting the click, and waiting for the content to appear—incurs a certain interaction cost." NN/g also flags "fragmented access to information": "If you expect users to need information from several accordions at once, it is better to display all the content at once," and "give people the capability to open multiple sections at a time" ([NN/g](https://www.nngroup.com/articles/accordions-on-desktop/); [NN/g](https://www.nngroup.com/articles/accordions-complex-content/)). Expansion fits *rarely changed* settings, must allow multiple rows open, and must keep key state legible when collapsed.

## 3. Bulk operations over long lists

The established admin pattern is a **selection-triggered action surface**, not per-row clusters. Carbon: "Once the user selects at least one row from the table, the batch action bar appears at the top of the table"; selection offers "a single-select radio button option and a multi-select checkbox option"; the toolbar holds "primary buttons, search, filtering, table display settings," with "no more than 5 icons" ([Carbon](https://carbondesignsystem.com/components/data-table/usage/)). Cloudscape: "Use global actions when there's a single set of actions, or bulk actions, to be taken against any or all resources," and, key for a 60–70 row scroll, "**If users need to take an action on resources upon selection, consider using a sticky header**" ([Cloudscape](https://cloudscape.design/patterns/general/actions/global-actions/)).

Select-all should handle the indeterminate case: a tri-state checkbox can "represent and control the state of an entire group" — all checked → checked, some → partially checked — and "the user can use the tri-state checkbox to change all options in the group with a single action" ([ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/)).

Every major system adds filtering and/or pagination rather than relying on scanning: Polaris index tables "include bulk actions," "support sorting and filtering of long lists," and "be paired with pagination to make long lists digestible" ([Polaris](https://polaris.shopify.com/components/tables/index-table)); Primer's header includes a filter "to make it easier for the user to focus only on the rows relevant to their task" ([Primer](https://primer.style/product/components/data-table/)); Atlassian paginates past one page ([Atlassian](https://atlassian.design/components/dynamic-table/usage)).

## 4. Accessibility

**Semantics.** "To tell assistive technologies that a button is a toggle button, specify a value for the attribute `aria-pressed`," and "**it is critical the label on a toggle does not change when its state changes**" ([ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/button/)). Segments need `role="group"` with per-segment `aria-pressed` ([MDC](https://github.com/material-components/material-components-web/tree/master/packages/mdc-segmented-button)), meeting [WCAG 1.3.1 (A)](https://www.w3.org/TR/WCAG22/#info-and-relationships).

**Target size — the binding constraint here.** [WCAG 2.2 SC 2.5.8 (AA, new)](https://www.w3.org/TR/WCAG22/#target-size-minimum) requires targets "at least 24 by 24 CSS pixels," with a Spacing exception requiring 24px-diameter circles centered on undersized targets not to intersect. Intent: "Some people with physical impairments cannot click small buttons that are close together," and sufficient size or spacing "will reduce the likelihood of accidentally activating the wrong control" ([W3C](https://w3c.github.io/wcag/understanding/target-size-minimum)). Four small chips × 70 rows is exactly that configuration.

**Keyboard traversal.** "Grouping controls into toolbars can also be an effective way of reducing the number of tab stops... the keyboard tab sequence includes one stop for the toolbar and arrow keys move focus among the controls" ([ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/)). A grid is composite: "only one of the focusable elements contained by the grid is included in the page tab sequence," but it "requires the author to provide code that manages focus movement inside it" ([ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)). ~450 tabbable controls is unusable.

Also: [2.4.7 Focus Visible](https://www.w3.org/TR/WCAG22/#focus-visible); [2.4.11 Focus Not Obscured (AA, new)](https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum) — focus must not be "entirely hidden due to author-created content," a risk with sticky bars; [1.4.1](https://www.w3.org/TR/WCAG22/#use-of-color) and [1.4.11](https://www.w3.org/TR/WCAG22/#non-text-contrast); [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard); [3.3.2 Labels or Instructions](https://www.w3.org/TR/WCAG22/#labels-or-instructions).

## 5. Critique of repeating controls per row

No major system names "toggle chips on every row," but Cloudscape states the operative principle: persist "**one or two** repetitive actions as a link or icon button... In case of **more than two actions, group them in a button dropdown to conserve space**," recommending the icon button dropdown "to **reduce visual noise and optimize content density**" ([Cloudscape](https://cloudscape.design/patterns/general/actions/incontext-actions/)). Four clusters per row far exceeds that.

The reasoning underneath is **interaction cost**: "the sum of efforts — mental and physical — that users must deploy in interacting with a digital product in order to reach their goals," decomposed into reading, scrolling, "looking around in order to find relevant information," comprehending, and clicking without mistakes ([NN/g](https://www.nngroup.com/articles/interaction-cost-definition/)). Repeated clusters inflate looking-around and comprehension multiplicatively with row count. The older "Oceans of Buttons" critique makes the same point ([Neil](https://archive.org/details/mobiledesignpatt0000neil_e4f9)), aligning with the [Aesthetic and Minimalist Design](https://www.nngroup.com/articles/ten-usability-heuristics/) heuristic.

---

## Recommended direction (ranked by expected impact)

1. **Collapse each row to a compact summary; move the four settings behind a row expansion.** Removes ~4 controls × 60–70 rows from the default view. Progressive disclosure "improves learnability, efficiency of use, and error rate" ([NN/g](https://www.nngroup.com/articles/progressive-disclosure/)); expandable rows "present large amounts of data in a small space" ([Carbon](https://carbondesignsystem.com/components/data-table/usage/)). Keep a one-line collapsed summary ([Android](https://source.android.com/docs/core/settings/settings-guidelines)) and allow **multiple rows open** ([NN/g](https://www.nngroup.com/articles/accordions-on-desktop/)).

2. **Add group-level bulk controls with tri-state select-all and a sticky action bar.** Batch bar on selection ([Carbon](https://carbondesignsystem.com/components/data-table/usage/)); sticky header for global actions ([Cloudscape](https://cloudscape.design/patterns/general/actions/global-actions/)); tri-state checkbox changes a whole group at once ([ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/)).

3. **Replace the four-chip cluster with one correctly-typed control per concept, in persistent columns.** Separate mutually-exclusive context length from independent booleans ([NN/g](https://www.nngroup.com/articles/checkboxes-vs-radio-buttons/)); cap inline segments at 2–5 ([Primer](https://primer.style/product/components/segmented-control/)). Fixed columns cut "looking around" cost ([NN/g](https://www.nngroup.com/articles/interaction-cost-definition/)).

4. **Add filtering (and pagination if needed).** Filtering helps "focus only on the rows relevant to their task" ([Primer](https://primer.style/product/components/data-table/)); Polaris pairs tables with pagination for "long lists" ([Polaris](https://polaris.shopify.com/components/tables/index-table)); Atlassian paginates past one page ([Atlassian](https://atlassian.design/components/dynamic-table/usage)).

5. **Enforce WCAG 2.2 target size and keyboard grouping on remaining inline controls.** Targets ≥24×24 px or 24px-spaced ([WCAG 2.5.8](https://www.w3.org/TR/WCAG22/#target-size-minimum)); one tab stop per group with arrow-key movement ([Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/), [Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)).

6. **Correct toggle semantics and state signalling.** `aria-pressed` with state-invariant labels ([ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/button/)); segments under `role="group"` ([MDC](https://github.com/material-components/material-components-web/tree/master/packages/mdc-segmented-button)); never convey on/off by color alone ([1.4.1](https://www.w3.org/TR/WCAG22/#use-of-color), [1.4.11](https://www.w3.org/TR/WCAG22/#non-text-contrast)).
